## 1. ログイン

## 2. ラボの作成と起動（自動保存）

1. ホームで「新規作成」（`lab-list__new-button`）→ トポロジエディタが開く。
2. 左のノードパレットから、ルーター（FRR）・L2スイッチ・PC を**ドラッグ&ドロップ**でキャンバスへ配置。
3. ノード同士をドラッグしてつなぐ → 「接続するインターフェースを選択」ダイアログで両端のI/Fを選び「接続」。
4. 編集は**自動保存**される（保存ボタンは無い）。ツールバーの **▶ 起動** でラボを起動する。
5. 起動中のまま、ノードの追加・削除、接続の追加・削除、VLANやアドレスの変更をする。

**期待結果**
- [ ] ノードを3種類（ルーター / L2スイッチ / PC）置ける
- [ ] 同じI/Fを2回使おうとすると「既に使用中のI/Fです」と出る
- [ ] 最初のノードを置くとその名前で保存され、ツールバーに「保存済み」と出る
- [ ] 保存後もラボ名欄を書き換えられ、ホームの一覧や別のPC・ブラウザから開いた時もその名前で表示される
      （起動中のラボでも作り直しは起きない。中のID＝コンテナ名などは最初の名前のまま変わらない）
- [ ] 既にあるラボと同じ名前では保存されず、名前を変えるよう表示される
- [ ] 「▶ 起動」で起動し、「● 起動中」の表示になる（初回は数十秒かかることがある）
- [ ] 起動中に編集すると「動いているラボに反映中...」→「保存・反映済み」と出て、変更が実際に反映される
- [ ] 起動中に編集しても、**変更していないノードは作り直されない**（ルーターの設定やPCのコンソールがそのまま）
- [ ] ホームに戻ってエディタで開き直しても、編集内容が残っている
- [ ] **Ctrl+Z（↶ボタン）で1つ前に戻せる**（ノード・接続の追加/削除、移動、接続設定の変更など）。
      Ctrl+Shift+Z / Ctrl+Y（↷ボタン）でやり直せる。コンソールや入力欄の中のCtrl+Zはそちらの操作になる
- [ ] 戻す／やり直すと、キャンバス上部に**何がどう変わったか**が数秒出る（例：「PC「pc-1」を削除（接続1本も）」
      「pc-1 eth1のIPアドレスを 10.0.0.1/24 → 10.0.0.2/24 に変更」）。変わったノード・接続は選択状態になる
- [ ] ↶↷ボタンにマウスを乗せると、押すと何が起きるかが出る
- [ ] ノードの右上のランプで状態が分かる：緑＝起動中、灰（ノードも薄く点線）＝停止中、黄の点滅＝起動/停止の処理中、
      黄の枠＝起動中のラボに追加してまだ反映されていない。ツールバーの「● 起動中/停止中/処理中」も同じ色
- [ ] 一部のノードだけ止めると、ツールバーが「● 起動中（3/4）」のようになる。マウスを乗せるとノードごとの状態が出る
- [ ] ホーム画面や別タブで起動/停止しても、10秒ほどでエディタの表示が追いつく

## 3. アドレス設定・VLAN・Router on a stick

どこで何を設定するか：

| 機器 | 設定する場所 |
| --- | --- |
| PC | GUI（接続ダイアログ。接続を右クリック →「設定を編集」で後から変更も可） |
| ルーター | コンソール（vtysh）。アドレス・ルーティング・サブインターフェースすべて |
| L2スイッチ | コンソール（Cisco風CLI）。VLAN・アクセス/トランク |

**3-1 PCのIP設定**（接続ダイアログで入力。例 `10.0.0.1/24`、ゲートウェイ `10.0.0.254`）
- [ ] 不正な形式（例 `10.0.0.1`）は入力時にエラーになる
- [ ] 起動後、PCのコンソールで `ip a` / `ip route` に設定が反映されている
- [ ] 起動中にアドレスやゲートウェイを変えると、そのPCに反映される
- [ ] ルーター側には、接続ダイアログにアドレスの入力欄が出ない

**3-1' ルーターのIP設定**（ルーターのコンソールで）
```
conf t
int eth1
 ip add 10.0.0.254/24
end
wr
```
- [ ] `sh int brief` / `sh run` に設定が出て、PCから `ping 10.0.0.254` が通る

**3-2 L2スイッチのVLAN**（スイッチを右クリック →「コンソールを開く」で設定。Ciscoと同じ要領で省略形・`?`・Tabが使える）
```
conf t
int eth1
 sw mo acc
 sw acc vl 10
int eth2
 sw acc vl 20
int eth3
 sw mo tr
 sw tr al vl 10,20
end
sh vlan br
wr
```
- [ ] 同じVLANのPC同士は `ping` が通る / 別VLANのPC同士は `ping` が通らない
- [ ] `sh vlan br` / `sh int status` / `sh int trunk` / `sh mac add` / `sh run` が表示される
- [ ] 何も設定していないポートはVLAN 1（全部同じVLAN）として通信できる
- [ ] 範囲外のVLAN（例 `sw acc vl 5000`）や間違ったコマンドは、間違えた位置に `^` が出て `% Invalid input detected` になる
- [ ] `?` で候補と説明が出る（`sw ?`、`conf?`）。Tabで補完できる（`int e` + Tab で `eth1 eth2 ...` の候補）
- [ ] Ctrl+Z で特権モード（`#`）に戻る。interfaceモードのままで `int eth2` と打つと別のポートに移れる
- [ ] `wr` してからスイッチを停止→起動すると設定が残り、`wr` していない変更は消える
- [ ] `wr` してからラボを「作り直す」（または停止→ホームで削除せずに起動し直す）と設定が残る（10/14〜ホスト側に保存）
- [ ] 接続ダイアログにVLANの入力欄は出ない（10/14で廃止）

**3-2b スパニングツリー（STP / RSTP / MSTP）**（10/14〜、スイッチは最初から `rapid-stp`（802.1w）で有効）

例：スイッチ3台を三角形につなぎ（ループ）、2台にPCを1台ずつつなぐ
```
sh spanning-tree                     ← Root ID / Bridge ID / 各ポートの Role・Sts（FWD/BLK）・Type（Edge等）
conf t
spanning-tree vlan 1 root primary    ← このスイッチをルートにする（priority 24576）
spanning-tree mode stp               ← 古典STP（802.1D）に切り替える（stp / rapid-stp / mstp の3つ、既定はrapid-stp）
int eth3
spanning-tree portfast               ← PCをつなぐポートはすぐ転送する（Edge）
spanning-tree bpduguard enable       ← BPDUを受けたらerr-disabledにする
end
```
- [ ] ループを組んでもPC同士の `ping` が通り、どれか1ポートが `Altn BLK` になる（サーバーが重くならない）
- [ ] `root primary` や `priority` でルートが変わり、`sh spanning-tree` に反映される。`sh run` に設定が出る
- [ ] 既定（`rapid-stp`）のまま通信中の経路のポートを `shutdown` すると、**ほぼ止まらずに**切り替わる（実測：0.2秒間隔のpingが1つも欠けない）
- [ ] 全スイッチを `spanning-tree mode stp` にして同じことをすると、**約50秒後**に迂回路で通信が戻る（古典STP）
- [ ] `portfast` を入れたポートは `sh spanning-tree` で `P2p Edge` になり、リンクアップ直後から通信できる
      （入れていないポートは、Ciscoと同じく起動直後や接続直後に約30秒待つ）
- [ ] BPDUが届くポート（スイッチ同士の `Altn` のポートなど）で `bpduguard enable` すると、`sh int status` で
      `err-disabled` になり相手は `notconnect` になる。`no spanning-tree bpduguard` → `shutdown` → `no shutdown` で戻る
- [ ] `spanning-tree guard root` / `bpdufilter enable` / `spanning-tree portfast default` / `spanning-tree portfast bpduguard default` が打てて `sh run` に出る

**MSTP**（VLANごとに別のツリー。3台とも同じリージョン設定にする）
```
conf t
vlan 10,20
interface range eth1-2
 switchport mode trunk
spanning-tree mode mstp
spanning-tree mst configuration
 name LAB
 revision 1
 instance 1 vlan 10
 instance 2 vlan 20
exit
spanning-tree mst 1 root primary     ← 1台目だけ。2台目は spanning-tree mst 2 root primary
end
sh spanning-tree mst / sh spanning-tree mst 1 / sh spanning-tree mst configuration
```
- [ ] MST1とMST2でルートが別のスイッチになり、ブロックされるポートがインスタンスごとに違う
- [ ] 注意：PVST（VLANごとに独立したSTP、Cisco独自）は無い。`spanning-tree vlan 10 ...` は全VLANに効く（注意が出る）。
      VLANごとに分けたいときはMSTPを使う

**3-2c スイッチの運用・管理の機能**（10/14〜、`fnl/l2switch:5`。既存のラボは「作り直す」が必要）

例：SW1・SW2をケーブル2本でつなぎ、それぞれにPCを1台、SW2にルーターを1台つなぐ

1. **ログ**：SW1のコンソールを開いたまま、GUIでSW1–SW2のケーブルを「抜く」→「差す」
2. **インターフェース**：`sh int eth1`、`sh int counters`、`clear counters`、`sh ip int br`
3. **MACテーブル**：PC同士でpingしてから `sh mac add`、`sh mac add int eth1`、`clear mac add dyn`、
   `conf t` → `mac add aging-time 60` / `mac add static 0011.2233.4455 vlan 1 int eth1`
4. **管理用SVI**：SW1で `int vlan 1` → `ip add 10.0.0.11 255.255.255.0` → `no sh`、PCから `ping 10.0.0.11`、
   SW1から `ping 10.0.0.2`（PCのアドレス）
5. **パスワード**：`enable secret cisco` → `line con 0` → `password lab` → `login` → `end` → `exit`
6. **LLDP/CDP**：両方のスイッチで `lldp run`。30秒ほど待って `sh cdp nei`、`sh lldp nei`、`sh lldp nei detail`
7. **EtherChannel**：両方のスイッチで `int range eth2-3` → `sw mo tr` → `channel-group 1 mode active`
   （片方は `passive` でもよい）。`sh etherchannel summary`、`sh lacp nei`、`sh spanning-tree`
8. **ポートセキュリティ**：PCのポートで `sw port-security` → `sw port-security mac-address sticky`。
   PCで `ip link add link eth1 name m1 type macvlan` → `ip a add 10.0.0.9/24 dev m1` → `ip link set m1 up` →
   `ping -I m1 10.0.0.2`（2台目の機器のつもり）。`sh port-security`、`sh port-security int eth1`、`sh int status`
   → `int eth1` → `shutdown` → `no shutdown`

**期待結果**
- [ ] 1：コンソールに `%LINEPROTO-5-UPDOWN ... changed state to down` と `%LINK-3-UPDOWN` が流れ、入力中の行は崩れない。
      `sh logging` にも残る。`conf t` → `end` で `%SYS-5-CONFIG_I`
- [ ] 2：BWが `100000 Kbit/sec`（リンクの品質の既定）。品質で帯域を変えると変わり、`sh spanning-tree` のCostも変わる
      （100Mbps→19、1Gbps→4）。pingを流すと「5 second input rate」とカウンタが増える
- [ ] 3：PCのMACが `DYNAMIC` で出て、`clear` で消える。staticは `STATIC` で出て `sh run` にも出る
- [ ] 4：`sh ip int br` で `Vlan1 10.0.0.11 ... up up`。PCとスイッチの間でpingが通る（`!!!!!`）。作った直後は
      administratively down（Ciscoと同じ）
- [ ] 5：コンソールを開き直すと `Password:` を聞かれ、入ると `SW1>`。`enable` でもパスワードを聞かれ `SW1#` になる。
      `sh run` に `enable secret 9 $9$...` が出る（平文では出ない）
- [ ] 6：相手のスイッチ（Capability `S` / `B`）とルーター（`R`）が出る。`no cdp enable` したポートは相手の `sh cdp nei` から消える
      （holdtimeが切れるまで最大120秒）
- [ ] 7：`Po1(SU)` と `eth2(P) eth3(P)`。`sh spanning-tree` にはeth2/eth3ではなく `Po1` が1本だけ出る（ループにならない）。
      GUIでeth2のケーブルを抜いてもPC間のpingは止まらず、`eth2(D)` と `%EC-5-UNBUNDLE` が出る
- [ ] 8：2台目のMACで通信すると `%PORT_SECURITY-2-PSECURE_VIOLATION` が出て eth1 が `err-disabled`。
      `sh run` に `switchport port-security mac-address sticky xxxx.xxxx.xxxx` が入っている。`shutdown` → `no shutdown` で戻る。
      `sw port-security violation restrict` にすると、元のPCの通信は続いたまま違反の数だけ増える

> 仕様：PAgP（desirable/auto）・PVST・SPAN・DHCPスヌーピングは無い。ルーター側でLLDP/CDPの近隣を見るコマンドは無い
> （スイッチ側から見る）。ルーターが名乗る名前はGUIのノード名（FRRではvtyshのhostnameが保存されないため）。

**3-3 Router on a stick**（ルーターのコンソールで設定する）

例：PC1（VLAN10）とPC2（VLAN20）をルーター1台でつなぐ
1. PC1・PC2・ルーターをL2スイッチにつなぐ。スイッチのCLIで、PC1のポートを access VLAN10、
   PC2のポートを access VLAN20、ルーターのポートを trunk にする（3-2の例と同じ）。
2. PC1は `10.10.0.2/24`・ゲートウェイ `10.10.0.1`、PC2は `10.20.0.2/24`・ゲートウェイ `10.20.0.1` を設定。
3. ラボを起動し、ルーターのコンソールで次を入力（`int` / `ip add` などの省略形でよい）。
```
conf t
int eth1.10
 ip add 10.10.0.1/24
int eth1.20
 ip add 10.20.0.1/24
```
- [ ] 1秒ほどでサブインターフェースが作られ、別VLANのPC同士がルーター経由で `ping` できる（PC側にデフォルトゲートウェイの設定が必要）
- [ ] `sh run` にサブインターフェースの設定が出る。`write memory` してノードを停止→起動しても残る
- [ ] `no ip add 10.20.0.1/24` で設定を消すと、eth1.20も消える（`sh int brief` で確認）
- [ ] 接続ダイアログに「VLANサブインターフェース」の入力欄は出ない（10/14で廃止）

## 5. ルーター・スイッチ設定の保存（`write memory`）

設定は自動では保存されません。残したいときに学生自身が `write memory`（`wr`）を実行する運用です。

1. ルーター（またはスイッチ）のコンソールで設定を変更 → `write memory`。
2. ラボを停止 → 起動。

**期待結果**
- [ ] 再起動後も `write memory` した設定が残っている
- [ ] **`write memory` していない設定は、停止→起動で消える**（仕様。実機の電源断と同じ）
- [ ] 起動中にトポロジを編集しただけでは、`write memory` していない設定も消えない

## 6b. リンクの品質・ケーブルの抜き差し（10/14〜）

リンクは何も設定しなければ**帯域100Mbps**（既定。品質ダイアログで「無制限」を選ぶと実測で約8Gbps）。リンクを右クリックすると
**「リンクの品質...」**と**「ケーブルを抜く／差す」**が出る。設定は自動保存され、動いているラボにはすぐ反映される。

例：PC-1 — SW1 — SW2 — PC-2 と、SW1–SW2の間にもう1本（ループ）をつないだラボ

1. PC-1とPC-2の間のリンクの1つを右クリック →「リンクの品質...」→ 遅延 `50` ms →「保存」。PC-1から `ping PC-2`
2. 「海外回線」「衛星回線」などのボタンで値をまとめて入れられる。帯域を `1 Mbps` 等にしてPCから大きめのping
   （`ping -s 1400 ...`）や連続した通信をしてみる
3. 「パケットロス」を `20` % にしてpingを打つ
4. スイッチ間のリンクを右クリック →「ケーブルを抜く」。両側のスイッチで `sh int status` / `sh spanning-tree`
5. もう一度右クリック →「ケーブルを差す」

**期待結果**
- [ ] 品質を設定したリンクは**紫の線**になり、ラベルに `10Mbps・50ms` のように内容が出る（既定の100Mbpsのままの線は灰色で、何も出ない）
- [ ] 「既定に戻す」で灰色の線に戻る。帯域で「無制限」を選ぶと注意書きが出て、ラベルに `帯域無制限` と出る
- [ ] 遅延50msでpingの往復時間が約100ms（行きと帰りの両方に掛かる）、ロス20%でおおよそ36%前後のpingが返らない
      （行きか帰りのどちらかで落ちる）

## 6c. ノードを初期状態に戻す（wipe）（10/15〜）

ノード（PC・ルーター・スイッチ）を右クリックすると **「初期状態に戻す（wipe）」** が出る（ラボを一度起動して、コンテナがある時だけ）。
write memoryした設定も含めて、そのノードの設定をすべて消し、コンテナを作り直す。他のノードとリンクは触らない。

例：R1 — SW1 — PC-1 のラボを起動し、R1で `hostname TEST` / `interface lo` / `description X` / `write memory`、
SW1で `vlan 77` / `write memory`、PC-1にアドレスを設定しておく

1. SW1を右クリック →「初期状態に戻す（wipe）」→ 確認で「OK」
2. 終わったら SW1のコンソールで `show vlan brief` / `show running-config`
3. R1を右クリック → wipe。R1のコンソールで `show running-config`
4. PC-1に設定していたアドレスを確認（1.でSW1をwipeしたあとも、PC-1のアドレスが残っているか）

**期待結果**
- [ ] 確認ダイアログが出て、キャンセルすると何も起きない
- [ ] SW1はVLAN 77が消え、ホスト名も初期の名前に戻る。ルーターはホスト名・loのdescriptionが消えている
- [ ] 他のノードはそのまま動き続ける（コンソールが切れない）。リンクはつながったまま、線の色（品質・ケーブル）も保たれる
- [ ] 隣のノード（PC-1）のアドレスも、wipeの後に入り直している（隣のvethが作り直されるため、一度消えて自動で戻る）
- [ ] 設定したリンクの品質（遅延など）が、wipeしたノードの端にも入り直している
- [ ] wipeの後にもう一度ラボを停止→起動しても、消した設定は復活しない
- [ ] ラボを停止している時と、ノードを停止している時は、wipeが出ない／ノードを起動してから行われる

> 仕様：APIの都合で、内部では「そのノードを除いたトポロジを反映→元に戻して反映」の2回の反映を行う（数十秒かかることがある）。

## 10. 仕様として知っておいてほしいこと

- **トポロジは自動保存・起動中は自動反映**（2026-10-14〜、CMLと同じ）：保存ボタンやDeployボタンはありません。
  起動中のラボを編集すると、変わった部分だけが反映され、他のノードは作り直されません。
  元に戻す（Ctrl+Z）も同じく反映されます。削除したノードを戻すと、新しいノードとして起動し直されます
  （中の設定は、ルーターなら `write memory` した内容が読み込まれます）。履歴はエディタを開いている間だけです。
  手元にも控えを持ちたいときは「エクスポート」を使います。
- **ルーターの設定は `write memory` で保存**：停止→起動（実機の電源断に相当）で、`write memory`（`wr`）
  していない設定は消えます。サブインターフェースも、スイッチのVLAN設定も同じです。
  一方、GUIで入れたPCのアドレスは起動のたびに自動で入れ直されるので消えません。
  スイッチの `write memory` もルーターと同じくサーバー側に保存されるので、「作り直す」をしても残ります
  （10/14夕方〜。ラボを削除すると消えます）。
- **スイッチのトランクはCiscoと同じ動き**：native VLAN（既定はVLAN 1）はタグなしで流れます。ルーターで
  VLAN 1 をサブインターフェース（eth1.1）にしても通らないので、VLAN 1 はルーターの物理I/F（eth1）に
  アドレスを付けるか、スイッチ側で `sw tr native vl 999` のようにnative VLANを変えてください。
- **サブインターフェースはvtyshで作る**（2026-10-14〜）：`int eth1.10` → `ip add ...` と打つと、ルーターが
  自動でVLAN10のサブインターフェースを作ります（VLAN IDは名前の「.」の後ろ）。消すときは `no interface` ではなく
  `no ip add ...` で設定を空にしてください（FRRの仕様で、動いているインターフェースは `no interface` できません）。
- **10/14より前に作ったラボは「古い形式」**：開くと「古い形式のラボのため、編集は保存のみで反映されません」と
  表示されます。「作り直す」を押すと今の形式で起動し直します（`write memory` していないルーター設定と、
  10/14夕方より前に置いたスイッチの設定は消えます）。
  以前GUIで入れたサブインターフェースとスイッチのVLANは引き継がれないので、CLIで設定し直してください。
  停止中のラボは、そのまま「▶ 起動」すれば今の形式で起動します。
- **BGPの `ebgp-requires-policy`**：FRRの仕様で、eBGPのネイバー間にルートポリシー（route-map等）が無いと、
  ネイバーがEstablishedになっても経路を送受信しません。BGPで経路が来ないときは、まずポリシーの設定
  （検証用なら `no bgp ebgp-requires-policy`）を確認してください。これは不具合ではなく仕様です。
