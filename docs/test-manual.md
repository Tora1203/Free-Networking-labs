# テストマニュアル（動作確認用）

最終更新: 2026-10-09 / kawase3（Claude Code補助）

Free-Networking-labs を触って「期待通り動くか」を確認してもらうための手順書。
各項目の **期待結果** と違ったら、末尾の「報告のしかた」に沿って教えてください。
不具合の報告は歓迎です（むしろそれが目的です）。

## 1. ログイン

1. ログイン画面でLinuxのユーザー名・パスワードを入力して「ログイン」。

**期待結果**
- [ ] ホーム（ラボ一覧）に遷移する
- [ ] 間違ったパスワードではエラーが表示され、遷移しない
- [ ] 他の人のラボが一覧に出ない

## 2. ラボの作成とデプロイ

1. ホームで「新規作成」（`lab-list__new-button`）→ トポロジエディタが開く。
2. 左のノードパレットから、ルーター（FRR）・L2スイッチ・PC を**ドラッグ&ドロップ**でキャンバスへ配置。
3. ノード同士をドラッグしてつなぐ → 「接続するインターフェースを選択」ダイアログで両端のI/Fを選び「接続」。
4. ラボ名を入力して **Deploy**。

**期待結果**
- [ ] ノードを3種類（ルーター / L2スイッチ / PC）置ける
- [ ] 同じI/Fを2回使おうとすると「既に使用中のI/Fです」と出る
- [ ] Deployが完了し、ノードが起動状態の表示になる（数十秒かかることがある）
- [ ] 変更後は「変更を反映」ボタンで再デプロイできる

## 3. アドレス設定・VLAN・Router on a stick

**3-1 PC / ルーターのIP設定**（接続ダイアログで入力。例 `10.0.0.1/24`、ゲートウェイ `10.0.0.254`）
- [ ] 不正な形式（例 `10.0.0.1`）は入力時にエラーになる
- [ ] Deploy後、PCのコンソールで `ip a` / `ip route` に設定が反映されている

**3-2 L2スイッチのVLAN**（接続ダイアログでポートごとに アクセス / トランク（全VLAN） / トランク（指定VLANのみ））
- [ ] 同じVLANのPC同士は `ping` が通る
- [ ] 別VLANのPC同士は `ping` が通らない
- [ ] VLAN IDに範囲外（例 5000）を入れるとエラーになる

**3-3 Router on a stick**（ルーター側で「VLANサブインターフェース」を追加、VLAN IDとアドレスを入力）
- [ ] 別VLANのPC同士が、ルーター経由で `ping` できる
- [ ] ルーターのコンソールで `vtysh` → `show ip route` に各VLANのネットワークが出る

## 4. 統合コンソール

1. デプロイ済みのノードを右クリック →「コンソールを開く」（または 🖥 ボタン）。

**期待結果**
- [ ] ブラウザ内にターミナルが開き、キー入力できる
- [ ] ルーターは `vtysh`、PCはシェルが動く（`ping`、`ip a` など）
- [ ] 複数ノードのコンソールがタブで開ける
- [ ] パネルを閉じると全コンソールが終了する
- [ ] L2スイッチは「コンソールがありません」（仕様）
- [ ] 未デプロイのノードでは開けない

## 5. ルーター設定の保存（`write memory`）

設定は自動では保存されません。残したいときに学生自身が `write memory` を実行する運用です。

1. ルーターのコンソールで `vtysh` → 設定を変更 → `write memory`。
2. ラボを停止（stop）→ 開始（start）、もしくは再デプロイ。

**期待結果**
- [ ] 再起動後も `write memory` した設定が残っている

## 6. パケットキャプチャ（Wireshark）

1. デプロイ済みのトポロジで、**リンクを右クリック →「パケットキャプチャ」**。
2. 新しいタブにWiresharkが開く。PC同士で `ping` を打つ。

**期待結果**
- [ ] 数秒〜数十秒で新しいタブが開き、Wiresharkの画面が出る（初回のみ少し遅い）
- [ ] **タブ名が `R1(eth1) ↔ SW1` のように**「どこをキャプチャしているか」を示している
- [ ] ICMP / ARP のパケットが流れて見える
- [ ] L2スイッチ側の端は対象外（ルーター/PC側だけ開く）— 仕様
- [ ] 未デプロイだとメニューが押せない
- [ ] **コピペ**：Wiresharkでパケットを右クリック → Copy → 任意の形式 → 手元のメモ帳等へ `Ctrl+V` できる
  （効かない場合：画面左端の矢印からクリップボード欄を開く）
- [ ] **タブを閉じる**と、数秒後にWiresharkコンテナが消える（kawase3が `docker ps | grep ws_vnc` で確認）

> 既知の制約：キャプチャを開いた「メイン画面」を先に閉じる/リロードすると、タブを閉じてもコンテナが残る。

## 7. エクスポート / インポート

1. デプロイ済みラボで「エクスポート」→ YAML（とannotations）がダウンロードされる。
2. 別の新規作成画面で「インポート」→ そのYAMLを選択。

**期待結果**
- [ ] ノード配置（座標）・接続・VLAN・アドレスが復元される
- [ ] `.yml` / `.yaml` 以外を選ぶとエラーになる

## 8. ラボのライフサイクル

ホームのラボカードから：

- [ ] 「開始 / 停止」ができ、状態表示が変わる
- [ ] 「削除」は確認ダイアログが出て、削除後に一覧から消える
- [ ] 「編集」でトポロジエディタが開き、保存済みの配置が復元される
- [ ] ラベル・エリア（見た目のみ）を置いて保存し、再度開いても残る

## 9. 見た目・その他

- [ ] ダーク / ライトの切り替えができる
- [ ] 画面幅を変えても操作不能にならない

## 10. 仕様として知っておいてほしいこと

- **保存はDeploy起点**：自動保存はしません（2026-10-09決定）。編集内容は **Deploy / 変更を反映** を押したときに
  サーバーへ保存されます。編集だけして押さずに離れると反映されないので注意してください。
  手元にも控えを持ちたいときは「エクスポート」を使います。
- **BGPの `ebgp-requires-policy`**：FRRの仕様で、eBGPのネイバー間にルートポリシー（route-map等）が無いと、
  ネイバーがEstablishedになっても経路を送受信しません。BGPで経路が来ないときは、まずポリシーの設定
  （検証用なら `no bgp ebgp-requires-policy`）を確認してください。これは不具合ではなく仕様です。
