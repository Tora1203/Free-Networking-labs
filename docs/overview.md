# 卒業制作 概要（チーム共有用）

このドキュメントは、このプロジェクトに初めて触れる人（チームメンバーやそのClaude）が読んで、
「何を作るのか」「なぜそれを作るのか」が経緯から分かるように書いたものです。
決定事項の最新状態は [`direction.md`](./direction.md) を参照してください。こちらは背景の説明用です。

## 課題感

商用のネットワークシミュレーションツール「Cisco Modeling Labs (CML)」は、無料版(CML Free)が
以下の制限を持っている：

- 単一ユーザー専用（複数人での同時利用に非対応）
- 同時起動ノード数が5台まで

一方、OSSの「Containerlab」はDocker上にネットワークOS（FRR等）を軽量に立ち上げられる
ツールで、YAMLでトポロジを定義しCLIで操作する。GitOpsとの相性は良いが、GUIが弱く
初心者には扱いにくい、という弱点がある（Containerlab公式もTopoViewer等でGUI化を
進めているが、まだ発展途上）。

## やりたいこと

**Containerlabをバックエンドにして、CMLのオープンソース版を作る。**

CMLのようなGUI操作感（ドラッグ&ドロップでのトポロジ編集、ブラウザ統合コンソール、
ノードのライフサイクル管理）を持ちながら、CML Freeの弱点だった「マルチユーザー非対応」
「ノード数上限」を持たないツールを目指す。教員/学生のような役割分けや授業運営機能は
今回のスコープには含めない（フラットなマルチユーザーでよい）。

## 今回のスコープ判断（要点）

- **対応ネットワークOSはFRRのみ**：商用ベンダーイメージ（vrnetlabでのVMラップが必要なもの）
  は準備・リソースコストが高いため見送り。FRRはネイティブコンテナで軽量に動き、
  BGP/OSPF等ひととおりの検証ができる。
- **外部ネットワークへのブリッジ接続は実装しない**：CMLのExternal Connector相当の機能は
  スコープ外。
- **ホスティングは研究室/学校の共有Linuxサーバー1台**：全員がそこに同居する構成。
- **認証はLinuxアカウンティングをそのまま利用**：独自のユーザーDB・認証システムは作らない。
  理由は下記アーキテクチャ節を参照。
- **最優先で作り込むのはGUIの使い勝手**：ドラッグ&ドロップ編集・状態のライブ可視化・
  統合コンソールがCMLらしさの核なので、ここに開発時間を集中させる。

## アーキテクチャ

```
［ブラウザ：React + React Flow(トポロジ編集) / xterm.js(統合コンソール)］
        │  REST（ラボ操作）／WebSocket（ターミナル・状態更新）
        ▼
［clab-api-server：PAM認証（Linuxアカウント）でユーザー・ラボ所有権を管理］
        │
        ▼
［containerlab CLI］
        │
        ▼
［Docker：FRRコンテナ群］
```

研究室/学校の共有Linuxサーバー1台の上に、上記すべてが同居する。

**認証をclab-api-serverに任せている理由**：clab-api-serverはLinuxのシステムアカウント＋
PAM認証で動作し、ラボを`$CLAB_LABS_ROOT/<username>/`のようにユーザー名ごとに自動で
分離・所有権管理してくれる。これを自作すると「マルチユーザーでのラボ分離」を一から
実装することになり、GUI開発に割ける時間が削られる。個別にLinuxアカウントを発行するだけで
「各自が自分のラボを持てる」が実現できるため、この土台をそのまま採用した。
（認証方式の選択肢や工数比較の詳細な議論は`direction.md`の履歴を参照）

**フロントエンドの技術選定の理由**：
- トポロジエディタに**React Flow (xyflow)**を選んだのは、ノード1つ1つに状態表示や
  コンソールを開くボタンなど独自UIを載せたく、Reactコンポーネントとしてノードを
  自由に描画できる点が今回の要件（CMLらしい操作感）に合っていたため。
  比較検討したCytoscape.jsは自動レイアウト機能が豊富だが、今回は手動配置が主なので
  オーバースペックと判断した。
- 統合コンソールには**xterm.js + WebSocket**を採用。ブラウザ内ターミナルの定番構成で、
  実績のあるパターン。

## 差別化ポイント（卒論としての新規性の置き所）

- Containerlab公式のGUIエコシステム（TopoViewer等）は既に存在するため、単純な
  「Web GUI化」だけでは新規性が薄い。差別化は、CML相当の操作感（ノードのライフサイクル
  管理、統合コンソールの完成度）の作り込みと、マルチユーザー・ノード数無制限という
  CML Freeにない性質に置く。

## まだ決まっていないこと

- 同時起動ノード数の上限など、簡易的なリソースガードレールを入れるかどうか
- リポジトリ構成、状態管理ライブラリ（Zustand/Reduxなど）の選定
