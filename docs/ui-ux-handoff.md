# UI/UXの見直し：作業の引き継ぎ（クラウドセッション向け）

2026-10-18。見た目と操作感を整える作業を、サーバー（ラボ用VM）に繋がらない環境でも進められるようにするためのメモ。

## 依頼の範囲

1. **全体の色合い**：`frontend/src/theme.css` のトークン（ライト／ダーク）を見直す。個別のCSSは色を直書きせず、トークンを使う。
2. **ボタン**：種類（通常・主要・危険・アイコン）と状態（hover・focus・disabled・押下中）をそろえる。今はツールバー、ダイアログ、ホームのカードで形がばらばら。
3. **レスポンシブ**：今は `@media` が1つも無い（`grep -rn "@media" frontend/src` で確認）。スマホ・タブレット幅でホーム、ログイン、エディタ（ツールバーの折り返し、ノードパレット、コンソールパネル、ダイアログの幅）が使えるようにする。

## 動かし方（サーバー不要）

```sh
cd frontend
npm ci
npm run dev:mock      # http://localhost:5173/ 。どのユーザー名・パスワードでもログインできる
```

- モックの実体は `frontend/src/mocks/mockServer.ts`。ブラウザの中で `fetch` と `WebSocket`（コンソール）を差し替える。
  本番のビルドには入らない。
- 最初から「校内ネットワーク（デモ）」（動いているラボ：ルーター2・スイッチ1・PC2）と「OSPFの練習（デモ）」（未起動）がある。
  ラボの起動・停止・削除、トポロジの編集と自動保存、差分反映、スナップショットの保存・戻す、エクスポートは動く。状態は再読み込みで初期化される。
- パスワードを `wrong` にするとログインエラーの表示を確かめられる。
- **動かないもの**：パケットキャプチャ（エラーを返す）、共有リンク、コンソールの実際のシェル（偽のシェルで、入力は返らない）、
  サーバー使用状況は固定気味の数字。ここの見た目の確認は実機（本番）で行う。

## 守ること

- **API・保存形式・ロジックは変えない**（`src/api/`、`src/utils/`、`src/store/`、各コンポーネントの処理部分）。見た目のCSSと、それに必要な最小限のマークアップだけを触る。
  ロジックに触れる必要が出たら、PRの説明に理由を書く。
- ダークモードを壊さない（`:root[data-theme='dark']`）。色はトークン経由。
- ダイアログの枠は `TopologyEditor.css` の `.topology-editor__modal`、`__modal-overlay` を共有している（リンクの品質、スナップショット、共有など）。変えるなら全部に効くことを前提にする。
- 画面の文言は日本語。既存の言い回しに合わせる。
- 確認：`cd frontend && npx tsc -b && npx vitest run && npx oxlint src && npm run build`（CIと同じ）。

## 画面の一覧（確認の観点）

| 画面 | ファイル | 見るところ |
| --- | --- | --- |
| ログイン | `LoginForm.tsx/.css` | 小さい画面での余白、エラー表示 |
| ホーム | `Home.tsx/.css` | ラボのカード、ボタンの種類（起動・停止・削除）、幅が狭い時の並び |
| エディタ | `TopologyEditor.tsx/.css`, `NodePalette.css` | ツールバーのボタンが多い（← ホーム、起動、インポート、エクスポート、スナップショット、共有…）。狭い幅での折り返し／まとめ方、パレットの置き場所 |

| ステータスバー | `ServerStatusBar.css` | 狭い幅 |
| ノード | `TopologyNode.css` | 状態のランプの見分けやすさ（色だけに頼らない） |
