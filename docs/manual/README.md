# 操作マニュアル（提出用）

読み手ごとに 3 冊に分けている。原稿は Markdown、提出用は PDF（同じ名前の `.pdf`）。

| 冊子 | 読み手 | 内容 |
|---|---|---|
| `操作マニュアル_利用者編` | 学生・利用者 | ログインから、ラボの作成、機器の設定、演習の例、リンクの品質、キャプチャ、困ったとき、コマンド一覧 |
| `操作マニュアル_管理者編` | サーバーの運用者 | 構成、新しいサーバーへのセットアップ、アカウント管理、日常の運用、バックアップ、セキュリティ、トラブル対応 |
| `操作マニュアル_評価者編` | 先生・評価者 | 目的、CML との比較、機能、設計と工夫、検証の結果、制約、15 分で確かめる手順 |

## PDF の作り方

サーバーに WeasyPrint や日本語フォントを入れずに済むよう、Docker で変換する（`tools/manual/`）。

```sh
docker build -t fnl/manual-build tools/manual
docker run --rm -u "$(id -u):$(id -g)" -v "$PWD/docs/manual:/work" fnl/manual-build
```

`docs/manual/*.md`（先頭が `_` または `README` のものを除く）が、それぞれ PDF になる。
図は `img/` の SVG。先頭の `# 題` が表紙の題、`<!-- subtitle: ... -->` が副題になる。
注意書きは `!!! note "題"` / `!!! warning "題"`（本文は 4 文字下げる）。

## 内容を更新するとき

機能を足したら、利用者編（使い方）と評価者編（機能一覧）、運用が変わったら管理者編を更新して、PDF を作り直す。
数値（テストの件数、行数、メモリの実測）は評価者編・管理者編にあるので、変わったら直す。
